## Example
```vue
<!-- Accessible modal: real dialog role, labelled title, focus moved in and restored on close -->
<script setup lang="ts">
import { nextTick, ref, watch } from "vue";

const props = defineProps<{ open: boolean; title: string }>();
const emit = defineEmits<{ close: [] }>();
const dialog = ref<HTMLElement | null>(null);
let lastFocused: HTMLElement | null = null;

watch(
  () => props.open,
  async (open) => {
    if (open) {
      lastFocused = document.activeElement as HTMLElement;
      await nextTick();
      dialog.value?.focus();
    } else {
      lastFocused?.focus();
    }
  },
);
</script>

<template>
  <div
    v-if="open"
    ref="dialog"
    role="dialog"
    aria-modal="true"
    aria-labelledby="dialog-title"
    tabindex="-1"
    @keydown.esc="emit('close')"
  >
    <h2 id="dialog-title">{{ title }}</h2>
    <slot />
    <button type="button" @click="emit('close')">Close</button>
  </div>
</template>
```

## Key points
- **Semantic HTML first**: a native `<button>`, `<label>` or `<dialog>` gives keyboard support and screen reader roles for free; ARIA is for gaps HTML can't fill.
- **Focus management**: every interactive element must be reachable by Tab with a visible focus ring, and focus must move into modals and return when they close.
- **Automated checks catch only part**: Lighthouse and axe find missing labels and low contrast, but keyboard and screen reader passes still need to be done by hand.
