### Detailed Findings by Severity

**[P1] One 2.86 MB JS chunk, nothing code-split**
- Location: build output `index-*.js` (2,860 kB, 901 kB gzip); `src/layout/elk.ts:2`, `src/components/DetailPanel.tsx:3`, `src/App.tsx` (static `GraphCanvas` import)
- Category: Performance
- Impact: The deep link sent to recruiters is often opened on a phone. The phone index needs neither ELK (`elk.bundled.js` is ~1.4 MB on its own) nor React Flow, yet both are parsed before the first paint. On a mid-range phone this is seconds of blank page.
- Recommendation: `lazy(() => import("./components/GraphCanvas"))` behind the existing `isPhoneLayout && !isPhoneMapShown` branch; lazy-load `rehype-highlight` with the card body, or register only the languages the content uses.
- Suggested command: `/impeccable optimize`

**[P2] ELK layout on the main thread**
- Location: `src/layout/elk.ts:2` (`elkjs/lib/elk.bundled.js`)
- Category: Performance
- Impact: The bundled build runs ELK in-thread, so each map switch blocks input while 75–168 nodes are laid out.
- Recommendation: Use `elkjs/lib/elk-api` with `workerUrl` pointing at `elk-worker.min.js` (Vite `?worker&url`), which also takes ELK out of the main chunk.
- Suggested command: `/impeccable optimize`

**[P2] Dimmed nodes below contrast minimum**
- Location: `src/styles/index.css:1077–1097` (spec at DESIGN.md:351)
- Category: Accessibility
- Impact: With a node selected, non-neighbour names measure 3.5:1 (`learned`), 3.8:1 (`work`), 2.2:1 (`planned`), meta lines 2.1:1. These nodes are still clickable, so WCAG 1.4.3 applies; low-vision visitors lose the context the spec says should "still read".
- WCAG: 1.4.3 Contrast (Minimum), AA
- Recommendation: Dim the band and fill but keep the title at ≥0.75 opacity (≈4.5:1 on paper); or record the trade-off in DESIGN.md as intentional.
- Suggested command: `/impeccable polish`

**[P3] Literal colours that duplicate or bypass tokens**
- Location: `src/styles/index.css:3` (`accent-color: #1f3bd6`), `:87` (`::selection` rgba of the accent), `src/content/load.ts:28` (`#94a3b8` fallback category, outside the palette)
- Category: Theming
- Impact: An accent change would have to be made in three places; the fallback grey is a Tailwind slate that no DESIGN.md token covers.
- Recommendation: `accent-color: var(--accent)`, `color-mix(in srgb, var(--accent) 18%, transparent)`, and a palette ink value for the fallback.
- Suggested command: `/impeccable polish`

**[P3] Canvas touch gestures unverified**
- Location: `src/components/GraphCanvas.tsx`
- Category: Responsive
- Impact: Pan and pinch on the phone `Map` view were not exercised; layout at 390px was checked only through the detector's emulated viewport (headless window screenshots below Chrome's minimum window width are unreliable).
- Recommendation: Run pan, pinch and an interrupted drag on a real phone or with synthesized touch.
- Suggested command: `/impeccable adapt`

### Patterns & Systemic Issues
- Performance has no loading strategy: every dependency lands in one eager chunk, including content (`import.meta.glob(..., { eager: true })`), which is fine today at 159 nodes but grows with every Markdown file.
- No accessibility pattern is systemic: the one real gap comes from a single spec decision, not from repeated drift.

### Positive Findings
- Overlays use `inert` on the author bar, toolbar, sidebar and workspace, so `aria-modal` dialogs genuinely contain focus.
- Search is a proper ARIA combobox (`aria-activedescendant`, `listbox`, `aria-expanded`); toggles use `aria-pressed`; map tabs use `aria-current`.
- Skip links, a single `h1`, landmark structure, focus-visible rings on every control including canvas nodes (8px in the far view).
- Camera motion honours `prefers-reduced-motion` in JS (`motionDuration`), CSS transitions are 120 ms colour/opacity only, no `will-change`.
- `@media (pointer: coarse)` lifts every control to 44px; browser surfaces (selection, scrollbars, caret, tabular numerals) are themed.
- `TechNode` is `memo`ized.
