### Detailed Findings by Severity

**[P2] Content is parsed and validated in the browser**
- Location: `src/content/load.ts:87–97` (eager `import.meta.glob` of raw Markdown and `maps.yaml`), main chunk 1,113 kB / 356 kB gzip
- Category: Performance
- Impact: Every visitor downloads `yaml` (~94 kB min), `effect` (~78 kB min) and every Markdown file raw, then parses and validates them before first paint. The phone reader pays for this most.
- Recommendation: Parse and validate at build time (a Vite plugin or virtual module emitting the built graph as JSON), keeping `npm run validate` as the gate. The client then ships data, not parsers.
- Suggested command: `/impeccable optimize`

**[P3] Palette mirrored as JS literals**
- Location: `src/components/GraphCanvas.tsx:46–52` (`EDGE_INK`: ink at 30/10/16%, accent, Ink 2, ink, paper), `:686` (`Background` colour = Grid Line), `src/layout/elk.ts:203` (arrow colour); `src/styles/index.css:993, 997, 1081` (`#ffffff` text on `practiced`, no token)
- Category: Theming
- Impact: A token change in `:root` leaves edges, labels, arrows and the grid on the old values. No user impact today.
- Recommendation: Pass `var(--accent)` / `color-mix()` strings where React Flow applies colour through `style`; check that each target is a style and not an SVG presentation attribute, which does not resolve `var()`. Add a `--on-ink-2` token for white on `practiced`.
- Suggested command: `/impeccable polish`

**[P3] Unused in-thread ELK shipped in the deploy**
- Location: `src/layout/elk.ts` (dynamic `elk.bundled.js` fallback for Node), build output `elk.bundled-*.js` 1,463 kB
- Category: Performance
- Impact: Browsers never request it (Worker always exists), so visitors pay nothing; the deploy carries 1.46 MB of dead weight.
- Recommendation: Resolve the fallback only in Vitest (`test.alias` in `vite.config.ts`) so the browser build never emits it.
- Suggested command: `/impeccable optimize`

**[P3] Gestures not yet confirmed on a physical phone**
- Location: `src/components/GraphCanvas.tsx`
- Category: Responsive
- Impact: Pan, pinch (on pane, node, group and edge), interrupted drag and tap pass under Chrome's synthesized touch at 390×844. iOS Safari, whose touch and pinch handling differs, is untested.
- Recommendation: One pass on an iPhone and an Android phone.
- Suggested command: `/impeccable adapt`

### Patterns & Systemic Issues
- Colour lives in two places: CSS tokens and a JS mirror inside the canvas. Every other surface reads tokens.
- The detector's `cramped-padding` on group plates recurs on every map and is a false positive; it adds noise to every scan.

### Positive Findings
- Status contrast holds in every node state, including dimmed; disabled filter counts fade by design and are WCAG-exempt.
- Phone readers load only the main chunk; the canvas (67 kB gzip) and ELK worker load on demand, with a loading frame that matches the canvas status bar.
- A drag or pinch starting anywhere on the canvas moves the map; mouse users keep edge hover labels.
- A stale deploy recovers with one reload and cannot loop.
- Focus, ARIA, `inert` overlays, skip links and 44 px coarse-pointer targets remain intact.
