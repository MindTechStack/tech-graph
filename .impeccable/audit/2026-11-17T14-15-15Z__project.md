### Detailed Findings by Severity

**[P3] Card bodies ship to every visitor**
- Location: `vite.config.ts` (`virtual:tech-graph-content` embeds every node's `body`), main chunk 956 kB / 298 kB gzip
- Category: Performance
- Impact: The index, search and graph need names, `what`, status and relations; the Example and Key points bodies (~228 kB of Markdown) are only read when a card opens, yet load up front.
- Recommendation: Emit bodies as a separate lazily loaded module (one per map, or one per node) and fetch on card open; keep `what` in the main data.
- Suggested command: `/impeccable optimize`

**[P3] Content errors do not fail a production build**
- Location: `vite.config.ts` built-content plugin; `src/App.tsx` (`hasInitialErrors` is dev-only)
- Category: Implementation Integrity
- Impact: A broken Markdown file is dropped silently from the deployed map; `npm run validate` catches it only if someone runs it.
- Recommendation: Throw from the plugin's `load` in `build` mode when diagnostics contain errors, or run `validate` in CI (task T7.3).
- Suggested command: `/impeccable harden`

**[P3] Gestures not confirmed on a physical phone**
- Location: `src/components/GraphCanvas.tsx`
- Category: Responsive
- Impact: Pan, pinch on pane/node/group/edge, interrupted drag, drag from a node and tap all pass under Chrome's synthesized touch at 390×844. iOS Safari is untested.
- Recommendation: One pass on an iPhone and an Android phone.
- Suggested command: `/impeccable adapt`

### Patterns & Systemic Issues

- Dimmed nodes hold ≥4.5:1; gestures work wherever a finger lands; mouse users keep edge hover labels.
- A stale deploy recovers with one reload and cannot loop.
